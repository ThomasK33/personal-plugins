# Verifier shadow study

The "Shadow verifier study" rule under `Swarm-verify once` in `SKILL.md` points here. This file holds the ledger format, the end marker, the terms and the final report.

## Terms

- **Primary:** the `swarm workers` verifier that the root briefs.
- **Shadow:** one of the two verifiers that get the same brief at the same head as the primary. `SKILL.md` sets their models.
- **Blocker class:** the root sorts every finding of every verifier as valid blocker, valid minor or invalid. It sorts them as it sorts any review finding.
- **Correct verdict:** PASS on a head with no valid blocker, or ISSUES that names at least one valid blocker of that head as a reason for ISSUES. The root counts the `later` column when it decides whether a head has a valid blocker.
- **False block:** ISSUES on a head with no valid blocker.
- **Miss:** a PASS on a head with at least one valid blocker, or an ISSUES on such a head that names none of its valid blockers as a reason for ISSUES.
- **Full head:** a PR head where the primary and both shadows gave a `VERDICT` line in one brief (one `brief_id`), and the primary ran on the `swarm workers` model with the brief that the shadows got. When the root replaces the primary with a verifier on another model, or with a reworded brief (after a crash or a refusal), that brief does not make any head that the replacement checks full. Its rows stay in `ledger-phase2.tsv` with that model.

## Ledger

Phase 2 starts at the merge of personal-plugins #42 (commit `f5c8bcf`). It ends when a root creates the end marker, the file `~/.xum/analysis/verifier-shadow/phase2-ended`. A phase 2 brief meets three conditions. A root sends it after the start. The root sends it under a version of the "Shadow verifier study" rule in `SKILL.md` that names two shadow models. The root's check just before the send found no end marker. A phase 2 brief can have a missing shadow. Each other brief that a root sends before its check finds the end marker is a phase 1 brief. A root writes no row for a brief that it sends after its check found the end marker.

Several roots share the ledgers and the end marker. A root holds an exclusive `flock` on `~/.xum/analysis/verifier-shadow/ledger.lock` while it reads or writes them. The lock covers each check for the end marker, each count of full heads, the creation of the marker or of a ledger file, each appended row and each `later` update. Before each verify brief and each time one of its shadows reports, a root checks for the end marker. A root checks for the marker and makes each `later` update in the same hold of the lock, and after an `early` marker it makes no `later` update. When the marker exists, the root sends any new brief to the primary only, writes no row for that brief, and stops each of its own shadows that is still running. After a root appends rows to `ledger-phase2.tsv`, it counts the full heads in the same hold of the lock. In that same hold, it checks for the end marker. When the count is 30 or more and no marker exists, it creates the marker with the word `30` in it. The marker is one line: `30`, or `early` and a line count, such as `early 57`. The line count counts every line of `ledger-phase2.tsv`, the header included. When a root finds an empty marker from an earlier version, it asks him whether the study ended early and writes his answer with the current line count. A replacement primary is part of its original brief, not a new brief, and gets rows only for the heads that it checks. A root can still start shadows after another root created the marker, until its next check. Such a shadow run costs money but changes no result. The cohort is the first 30 full heads in line order, and an early report uses only the lines of `ledger-phase2.tsv` up to the line count in the marker.

Phase 2 has its own ledger, `~/.xum/analysis/verifier-shadow/ledger-phase2.tsv`. The root writes no row of a phase 2 brief to the phase 1 file, `ledger.tsv`. The root creates the phase 2 file on first use with this header row:

```
date_utc	repo	pr	head_sha	brief_id	role	model	task_id	verdict	cost_usd	wall_min	brief_prs	blockers	later
```

`brief_id` is the task ID of the first primary of that brief, and all verifiers of one brief share it, a replacement primary included. `role` is `primary` or `shadow`. When a phase 1 brief ends after phase 2 starts, the root writes its rows to `ledger.tsv` with that file's own columns.

1. The root writes the rows of a verifier when its task ends for any reason: it gave its last report, after the root asked again for any missing `VERDICT` line, or the root stopped it, or it failed. It writes one row per PR head of the brief, and a replacement primary one row per head that it checks. The root writes no row for an interim report or a question.
2. `verdict` is `PASS`, `ISSUES`, or `none` when the verifier ended without a `VERDICT` line for that head.
3. `cost_usd` is the verifier's subtree cost from `session-usage.json` when its task ends. `wall_min` is the minutes from the brief to the end of the task. `brief_prs` is the number of PRs in that brief. The rows of one verifier for one brief repeat the same cost and wall time, so divide by `brief_prs` before summing.
4. `blockers` lists each finding that the verifier named, each with its blocker class, and marks the ones it gave as a reason for ISSUES.
5. Until the cutoff of a head, the root adds each blocker that a later review or commit shows on that head to `later` on every row of that head. When it writes a row after such a blocker, the row gets the same `later` value. The root leaves `blockers` as it is. The cutoff of a head is the moment someone merges or closes its PR, or the moment a root creates an `early` end marker, whichever comes first. A `later` update that a root writes after the cutoff does not change the ledger.

## Final report

The report counts one brief per head: the brief whose row first makes the head full, in line order of `ledger-phase2.tsv`. Its rows are the counted rows of that head, and the report uses no other rows of that head. The phase 2 cohort is the first 30 full heads in `ledger-phase2.tsv`, in line order of the row that makes each head full. When the root that writes that row for the 30th full head finds no end marker, it creates the marker with the word `30` and stops each of its own shadows that is still running. The root that creates the end marker tells him in its next reply that phase 2 has ended, and lists the cohort PRs whose cutoff has not passed. No root owns the final report: he asks one root for it, and that root writes it. When he tells a root to end the study early, that order is also his request for the report. A brief whose shadow the root stopped before that shadow gave its `VERDICT` line for the head does not make that head full, and a brief that made that head full in an earlier line still counts. After a normal end, the root that writes the report waits until the cutoff of each head in the cohort has passed. When he ends the study early, the root that he tells checks for the end marker and, when none exists, creates it in the same hold of the lock, with `early` and the current line count of `ledger-phase2.tsv`. When the marker already exists, the study has already ended. The root tells him so and writes the report only when he asks for it again. When the root created the marker, it stops each of its own shadows that is still running, writes their rows and reports at once. The moment it creates the marker is the cutoff for every open PR. An early report uses only the lines of `ledger-phase2.tsv` up to the line count in the marker, so any root writes the same report from it. Rows written after that line, the rows of the stopped shadows included, do not count. A primary that is still running keeps checking its PR, and its brief does not make its head full.

The report holds:

1. Correct verdicts, false blocks and misses for each model, over the counted rows of the cohort.
2. Valid blockers that only one model found, and for each shadow the valid blockers that it found and the primary missed, in the counted rows of the cohort.
3. Cost and wall time for each model, over its counted rows of the cohort.
4. The heads of phase 2 briefs in `ledger-phase2.tsv` that were not full, with the role, the model and the reason: no shadow row (shadow missing, or a shadow of another root still running at an early report), shadow stopped, shadow failed, shadow ended without a `VERDICT` line, primary stopped, failed or ended without a `VERDICT` line, primary still running at an early report, or primary on another model or with a reworded brief.
